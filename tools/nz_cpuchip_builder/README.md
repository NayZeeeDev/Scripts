# nz_cpuchip builder

Everything in `nz_cpuchip/stream/` is generated by `build_cpu_chip.py` – no
3ds Max / Blender needed. Rebuild when you want to change the size, the brand
text, colours, the pad grid, the collision material or the archetype flags.

```
tools/nz_cpuchip_builder/
├─ build_cpu_chip.py     generator (numpy + Pillow)
├─ dist/                 last build: CodeWalker XML + DDS textures + .glb
│  ├─ source/nz_prop_cpu_chip.ydr.xml
│  ├─ source/nz_prop_cpu_chip.ytyp.xml
│  ├─ source/nz_prop_cpu_chip/*.dds       (diffuse _d, normal _n, specular _s)
│  └─ nz_prop_cpu_chip.glb                (open in Blender / any glTF viewer)
└─ preview/              headless three.js renderer (node + playwright)
```

## 1. Generate

```bash
pip install numpy pillow
python3 build_cpu_chip.py --out out            # writes out/source/… , out/preview/… , out/nz_prop_cpu_chip.glb
python3 build_cpu_chip.py --out out --archetype-flags 32 --lod-dist 80
```

Tweakables are the constants at the top of the script (dimensions in metres,
atlas regions, colours) and the text lines in `paint_ihs_top()`.

## 2. Convert XML -> .ydr / .ytyp

**Option A – CodeWalker (Windows, GUI).** Open CodeWalker RPF Explorer, enable
*Edit mode*, browse to any folder, right click -> *Import XML…*, pick
`out/source/nz_prop_cpu_chip.ydr.xml` (it finds the DDS files in the
`nz_prop_cpu_chip/` folder next to it) and `nz_prop_cpu_chip.ytyp.xml`.
Copy the resulting `.ydr` / `.ytyp` into `nz_cpuchip/stream/`.

**Option B – `tools/cwtool` (any OS, command line).** A tiny .NET 8 console app
on top of CodeWalker.Core that does the same conversion and can load the
binaries back to verify them:

```bash
cd tools
git clone --depth 1 https://github.com/dexyfex/CodeWalker        # CodeWalker.Core builds on Linux/macOS/Windows
cd cwtool && dotnet build -c Release
dotnet bin/Release/net8.0/cwtool.dll ydr  ../nz_cpuchip_builder/out/source/nz_prop_cpu_chip.ydr.xml ../nz_cpuchip_builder/out/source/nz_prop_cpu_chip ../../nz_cpuchip/stream/nz_prop_cpu_chip.ydr
dotnet bin/Release/net8.0/cwtool.dll ytyp ../nz_cpuchip_builder/out/source/nz_prop_cpu_chip.ytyp.xml ../../nz_cpuchip/stream/nz_prop_cpu_chip.ytyp
dotnet bin/Release/net8.0/cwtool.dll inspect ../../nz_cpuchip/stream/nz_prop_cpu_chip.ydr   # prints shaders, textures, geometry, bounds
```

**Option C – Blender + Sollumz.** Import `dist/nz_prop_cpu_chip.glb` (or the
`.ydr.xml` directly with Sollumz), edit, and export as `.ydr.xml`, then convert
as above.

## 3. Preview renders (optional)

```bash
cd preview && npm install && npx playwright install chromium
node render.mjs --assets ../out/preview --out ../out/renders      # iso / top / bottom / side / icon PNGs
```

## Format notes (what the generator writes and why)

* **Drawable**: one model, one geometry, vertex layout `GTAV1` with
  Position / Normal / Colour0 / TexCoord0 / Tangent (stride 52), front faces
  counter-clockwise, `FlagsHigh = 1` (number of high-LOD models).
* **Shader**: `normal_spec` (`normal_spec.sps`), parameters in the game's order
  (DiffuseSampler, BumpSampler, SpecSampler, HardAlphaBlend, useTessellation,
  wetnessMultiplier, bumpiness, specMapIntMask, specularIntensityMult,
  specularFalloffMult, specularFresnel).
* **Textures** are embedded in the drawable (no separate .ytd needed). Normal
  map is DirectX style (green = down), which is what GTA expects; the `.glb`
  gets a green-flipped copy for Blender/glTF viewers. Tangent `w` is chosen so
  `cross(tangent, normal) * w` is the +v direction, matching the game's shader.
* **Collision**: composite bound with a single box child (margin = min side / 8,
  volume and inertia of a solid box), material index 86 = PLASTIC, composite
  flags from Sollumz's "General (Default)" preset.
* **Archetype**: `CBaseArchetypeDef`, `ASSET_TYPE_DRAWABLE`, empty
  `textureDictionary` / `physicsDictionary` (both embedded), flags `0`
  (dynamic), `lodDist 50`, `hdTextureDist 15`.
