Shoebox to prop, start to finish

Style it here, import it in CodeWalker, drop it in the stream folder. No Blender.

1Style the box

  • Pick a colourway preset or set the four colours yourself. Print is the colour of the brand text, the monogram and the lid border.
  • Type the brand and small print. Add a logo with Use file…. A transparent PNG looks best. With no logo, the lid gets a round monogram made from the brand's initials.
  • The viewport shows exactly what gets built: same mesh, same texture, same hinge. Hit Open under the box to check the lid swing, or the loop button to keep it going.
  • UV check swaps in a checker so you can see how the texture maps. Shaded shows the bare mesh.

2Size and name

  • Pick Kids, Men's or Boot, or type your own size in centimetres. The lid hinge moves with the size, and the config snippet carries the matching HingeOffset.
  • Name it. Lowercase and underscores only, and unique across the server: nz_shoebox_red, not box. The lid is always <name>_lid.
  • Making more than one colourway? Build each one under its own name.

3Build

  • Hit Build package. You get <name>.zip.
<name>.zip <name>\ <name>.ydr.xml the box <name>\ its texture <name>_lid.ydr.xml the lid, origin on the hinge <name>_lid\ its texture <name>.ytyp.xml both archetypes README.txt fxmanifest-snippet.lua config-snippet.lua atlas-preview.png

4Import it in CodeWalker

  • Unzip anywhere. Don't move or rename the texture folders. CodeWalker looks for a folder named exactly like the XML, right next to it. Moving one gives you Texture file not found.
  • Open RPF Explorer, browse into the unzipped <name> folder, right-click → Import XML.
  • Select all three: <name>.ydr.xml, <name>_lid.ydr.xml and <name>.ytyp.xml. You get a real .ydr, _lid.ydr and .ytyp.

5Into the stream folder

  • Make a folder for the box inside the resource's stream folder and put the three built files in it.
  • No .ytd. The texture is inside each .ydr.
sneaker_box\stream\ nz_shoebox\ nz_shoebox.ydr nz_shoebox_lid.ydr nz_shoebox.ytyp

6fxmanifest and config

  • One DLC_ITYP_REQUEST line per ytyp, with the real path including the subfolder:
data_file 'DLC_ITYP_REQUEST' 'stream/nz_shoebox/nz_shoebox.ytyp'
  • Paste config-snippet.lua over the model lines at the top of sneaker_box/config.lua. It sets BaseModel, LidModel and the HingeOffset for this size.
  • Restart the server, then fully restart your client and clear cache. FiveM caches streamed models and will keep showing the old one.

7Try it in game

  • /shoebox puts one in front of you. Press E, or use ox_target, to open and close it. Everyone nearby sees the lid swing.
  • /shoebox_delete removes the closest box you placed.

8When it goes wrong

Texture file not found on import The texture folder isn't next to the XML, or got renamed. Unzip again and import from inside the <name> folder.
model is not streaming Check three things, in this order: the DLC_ITYP_REQUEST line exists and its path is right, the .ytyp is in that folder, and the names in config match the .ydr filenames exactly.
The box spawns but the lid floats or sits inside the box HingeOffset in config doesn't match the size you built. Paste the config snippet from this build.
Box looks white or flickers The import used an old XML. Rebuild, import again, and clear your client cache.
Old version keeps showing Client cache. Close FiveM completely, delete the cache folder, relaunch.
